DILIVOX — ЧТО CHATGPT ДОЛЖЕН ПОДГОТОВИТЬ ДЛЯ НОВОГО КОМИКСА

Этот файл можно целиком передать ChatGPT перед подготовкой комикса.


ЦЕЛЬ

Подготовить полный контентный пакет комикса Dilivox, который Codex сможет без переписывания сюжета собрать в рабочую Tilda/T123-страницу.

Комикс является историей Dilivox и входит в общий каталог:
https://dilivox.ru/istorii/

URL комикса:
https://dilivox.ru/istorii/[slug]/

Отдельный каталог /komiksy/ и отдельные жанровые URL не создавать.

Первый комикс продолжает общую нумерацию и получает номер 49. Следующие комиксы получают номера 50, 51 и далее.


1. ГЛАВНАЯ МЕХАНИКА

Комикс должен сохранять механику Dilivox:

сюжет -> заметные детали -> выбор версии -> развязка -> объяснение улик

До выбора версии читатель не должен видеть кадры развязки и правильный ответ.

Вариантов ответа должно быть ровно четыре. Правильный вариант должен быть ровно один.


2. ПАПКА КОМИКСА

Папка:
10-comics-content:/NN-slug:/

Пример:
10-comics-content:/49-tayna-nochnogo-tramvaya:/

В папке ChatGPT должен подготовить четыре файла:

1. dilivox-comic-NN-slug-content.txt
2. dilivox-comic-NN-slug-frames.json
3. dilivox-comic-NN-slug-visual-bible.txt
4. dilivox-comic-NN-slug-for-codex.txt

Не создавать T123, HEAD и рекламный код. Их собирает Codex по действующей системе проекта.


3. CONTENT.TXT

Файл dilivox-comic-NN-slug-content.txt должен содержать:

Номер истории:
[NN]

Название:
[полное название]

URL:
https://dilivox.ru/istorii/[slug]/

Slug:
[slug латиницей]

Видимый жанр:
[жанр]

data-dv-genre:
[значение жанра]

data-dv-format:
[short | medium | series]

data-dv-story-type:
comic

Возрастная категория:
[0+ | 6+ | 12+ | 16+ | 18+]

Возраст выбирать по содержанию конкретного комикса. Не ставить 16+ автоматически.

Lead страницы:
[2–3 предложения без спойлера]

Описание для карточки каталога:
[2–3 предложения без спойлера]

Метки карточки:
[ровно 4 короткие метки]

SEO Title:
[вариант]

SEO Description:
[вариант]

Keywords:
[вариант]

Полный сценарий:
- последовательность сцен;
- текст авторских подписей;
- все реплики персонажей;
- важные визуальные детали и улики;
- точное место выбора версии;
- четыре варианта ответа;
- номер правильного варианта;
- полный текст развязки;
- список «Что решило дело» из 4–7 пунктов.

Предыдущая опубликованная история:
https://dilivox.ru/istorii/pansionat-tikhiy-uzhas/

Следующую историю указывать только тогда, когда она полностью готова к публикации.


4. КАДРЫ И ФОРМАТ 4:5

Все сюжетные кадры должны иметь строгое соотношение сторон 4:5.

Рекомендуемый исходный размер:
1080 x 1350 px.

Для каждого кадра обязательно подготовить:
- порядковый номер;
- номер сцены;
- назначение: story или reveal;
- реальный URL изображения после загрузки на Tilda;
- ширину и высоту;
- краткий alt-текст без художественного пересказа;
- точную текстовую расшифровку всего написанного в кадре;
- отдельно реплики, авторскую подпись и звуковые надписи;
- описание важной улики, если она есть;
- отметку о завершении сцены.

Даже если реплики уже нарисованы внутри изображения, их текст обязательно продублировать в манифесте. Это нужно для доступности, поиска и проверки опечаток.

Первый кадр можно использовать как обложку, если композиция выдерживает безопасное кадрирование для карточки каталога. Если не выдерживает, подготовить отдельную обложку и указать её URL.

Не выдумывать готовые URL. Если изображения ещё не загружены на Tilda, ставить понятные значения:
[IMAGE_URL_FRAME_01]
[IMAGE_URL_FRAME_02]

Финальная сборка для заливки начинается после замены всех таких значений на реальные URL.


5. FRAMES.JSON

Файл dilivox-comic-NN-slug-frames.json должен быть валидным JSON без комментариев.

Структура:

{
  "story_number": 49,
  "title": "Название комикса",
  "slug": "slug",
  "url": "https://dilivox.ru/istorii/slug/",
  "genre_label": "Видимый жанр",
  "genre_value": "data-dv-genre",
  "format": "short",
  "story_type": "comic",
  "age": "12+",
  "lead": "Лид без спойлера",
  "catalog_description": "Описание карточки без спойлера",
  "tags": ["метка 1", "метка 2", "метка 3", "метка 4"],
  "cover": {
    "image_url": "[IMAGE_URL_COVER]",
    "width": 1080,
    "height": 1350,
    "alt": "Обложка комикса «Название»",
    "focal_point": "center"
  },
  "frames": [
    {
      "number": 1,
      "scene": 1,
      "phase": "story",
      "image_url": "[IMAGE_URL_FRAME_01]",
      "width": 1080,
      "height": 1350,
      "alt": "Краткое описание кадра",
      "caption": "Авторская подпись или пустая строка",
      "dialogue": ["Первая реплика", "Вторая реплика"],
      "sound_text": ["Текст звуковой надписи или пустой массив"],
      "transcript": "Полная текстовая расшифровка кадра в порядке чтения",
      "clue": "Описание улики или пустая строка",
      "scene_break_after": false
    }
  ],
  "choice": {
    "after_frame": 12,
    "question": "Какая версия объясняет все детали?",
    "options": [
      {"id": 1, "text": "Версия 1", "correct": false},
      {"id": 2, "text": "Версия 2", "correct": true},
      {"id": 3, "text": "Версия 3", "correct": false},
      {"id": 4, "text": "Версия 4", "correct": false}
    ]
  },
  "reveal": {
    "start_frame": 13,
    "explanation": "Полное объяснение правильной версии",
    "proof": [
      "Улика 1",
      "Улика 2",
      "Улика 3",
      "Улика 4"
    ]
  },
  "navigation": {
    "previous_slug": "pansionat-tikhiy-uzhas",
    "next_slug": ""
  }
}

Правила JSON:
- номера кадров не пропускать и не дублировать;
- phase до выбора: story;
- кадры развязки: reveal;
- reveal.start_frame должен совпадать с первым кадром phase=reveal;
- choice.after_frame должен быть последним видимым кадром до выбора;
- ровно один option должен иметь correct=true;
- в tags должно быть ровно четыре значения;
- width/height каждого сюжетного кадра должны сохранять 4:5.


6. VISUAL-BIBLE.TXT

Файл dilivox-comic-NN-slug-visual-bible.txt нужен для визуальной непрерывности.

В нём указать:
- общий художественный стиль;
- палитру;
- освещение;
- время и место действия;
- внешность каждого постоянного персонажа;
- одежду каждого персонажа по сценам;
- постоянные предметы и отличительные признаки;
- устройство основных локаций;
- правила расположения реплик и порядка чтения;
- запрещённые визуальные изменения;
- единый negative prompt или список нежелательных артефактов;
- точные промпты или краткие производственные описания для каждого кадра.

Имена, одежда, цвет волос, возраст, важные предметы и расположение улик не должны самопроизвольно меняться между кадрами.


7. FOR-CODEX.TXT

Файл dilivox-comic-NN-slug-for-codex.txt должен быть коротким паспортом пакета:

- номер истории;
- название;
- URL;
- slug;
- видимый жанр;
- data-dv-genre;
- data-dv-format;
- data-dv-story-type="comic";
- возраст;
- общее количество кадров;
- номер последнего сюжетного кадра;
- номер первого кадра развязки;
- номер правильной версии;
- URL обложки;
- список всех URL кадров по порядку;
- описание карточки каталога;
- четыре метки;
- предыдущая история;
- следующая история только при её готовности;
- список файлов пакета;
- список незаполненных значений и отсутствующих URL.


8. ЧТО CHATGPT НЕ ДОЛЖЕН ДЕЛАТЬ

Не создавать:
- отдельный каталог /komiksy/;
- URL с жанром или форматом;
- T123-код;
- HEAD-код;
- JSON-LD;
- код РСЯ;
- локальный JavaScript;
- собственную механику progress/localStorage;
- собственную механику выбора версии;
- шапку и футер;
- счётчик Метрики;
- пустые ссылки на будущие страницы;
- заглушки, предназначенные для публикации на сайте.

Не менять:
- домен dilivox.ru;
- путь /istorii/[slug]/;
- общую нумерацию историй;
- механику «сюжет -> выбор версии -> развязка».


9. ЧТО СДЕЛАЕТ CODEX

После получения полного пакета Codex:
- проверит сюжетные и технические связи;
- соберёт адаптивную вертикальную страницу под кадры 4:5;
- добавит data-dv-story-type="comic";
- добавит выбор версии и скрытую развязку;
- подключит progress и localStorage через систему Dilivox;
- расставит РСЯ между завершёнными сценами, не внутри диалогов;
- подготовит T123, HEAD, SEO и JSON-LD;
- добавит карточку в общий каталог /istorii/;
- обновит навигацию, sitemap и URL-карту;
- проверит мобильную и десктопную вёрстку.


10. ФИНАЛЬНАЯ ПРОВЕРКА CHATGPT

Перед передачей пакета проверить:

1. Все кадры имеют 4:5.
2. Номера кадров последовательны.
3. Все реплики продублированы текстом.
4. У каждого кадра есть alt и transcript.
5. Все важные улики видимы до выбора версии.
6. Кадры развязки помечены phase=reveal.
7. Есть четыре версии и только одна правильная.
8. Есть полное объяснение и 4–7 решающих улик.
9. Возраст назначен по содержанию.
10. Жанр, формат и тип comic не смешаны.
11. Нет выдуманных готовых URL.
12. Все незаполненные поля перечислены в for-codex.txt.
13. T123, рекламу и глобальный JavaScript ChatGPT не создавал.
