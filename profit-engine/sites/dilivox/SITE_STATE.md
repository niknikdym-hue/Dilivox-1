Canonical domain: `dilivox.ru`

## Role in platform

Dilivox is the first full production SiteAgent/reference implementation of the shared Profit Engine.

It is not merely a landing site. Launch requires the complete closed loop:

`Yandex Direct -> Dilivox -> user behavior -> YAN revenue -> reconciliation -> Profit Engine -> guarded Direct + Dilivox action -> measured result`.

Nothing in the shared core may assume Dilivox is the only site.

## Economic target

Primary target:

`K5 = YAN revenue attributable to acquired Dilivox audience / Yandex Direct spend >= 5.0`.

Operational views must retain 1D/7D/30D cohort windows and observed/estimated/reconciled state rather than silently conflating them.

## Revenue scope

Launch target revenue is YAN/RСЯ advertising-block revenue generated by legitimate real use of Dilivox.

YAN is provider #1. Site instrumentation and placement registry must be provider-neutral so additional ad networks can be connected later.

## Mandatory Dilivox launch work

Full specification: `profit-engine/DILIVOX_SITE_INTEGRATION.md`.

## Advertising-machine relationship

The machine may use Dilivox as a structured source for campaign/creative generation.

`CampaignFactory + CreativeFactory` should be able to consume eligible Dilivox content metadata/assets and create bounded Direct tests without requiring Owner routine ad-ops work.

The site must provide truthful landing/content metadata so generated ads do not misrepresent the destination.
